# 실험 기록: 전환 정의 변경 재학습 (IP 매칭 시드, 층화 pool + 불균형 대응)

날짜: 2026-07-09. 이전 기록: [`202607091533.md`](202607091533.md)(스키마 진단, 절대 매칭
건수, 재학습 없이 돌린 1차 백테스트). 관련 코드/쿼리: [`querys/addi_conv/`](../../querys/addi_conv/)
12~14번, `scoring.build_stratified_pool`, `scoring.train_supervised_lookalike`,
[`README.md`](../../README.md) §2-6.

## 배경

1차 백테스트(`202607091533.md`)에서 재학습 없이 기존 T2+ 시드 모델로 IP 매칭 전환 라벨을
검증한 결과, 하위권은 걸러지지만 상위권 순위가 깨끗하지 않은(8구간이 10구간보다 높음) 약한
신호만 확인됐다. "재학습해볼 가치는 있다"는 판단으로, 그 문서의 "다음 단계" 1~4번을
실제로 적용했다.

## 1. 5% 샘플링 문제 해결 (층화 pool 조립)

학습 pool(`user_profile_apr_may.csv`, `media_sequence_apr_may.csv`)은 데이터량 때문에 유저
단위 5% 샘플링이 걸려 있다. 4~5월 IP+cmp_no 매칭 유저(양성 후보)는 412명뿐이라, 이대로면
5% 샘플 안에 ~20명만 남아 학습이 사실상 불가능했다.

- `querys/addi_conv/12_conv_matched_users_apr_may.sql`: 매칭 유저 목록을 req_user_id 기준
  485명으로 뽑음(08번의 distinct ifa 412명과 다른 건 device_ifa:req_user_id가 1:N인 경우가
  있어서 — `docs/addi_raw_data_schema.md` 기존에 알려진 흔들림).
- `13/14_conv_matched_users_*_apr_may.sql`: 이 485명의 프로필/미디어 방문을 5% 샘플링 없이
  전수 조회. 프로필 396명, 미디어 428명(5개 미만 이벤트 유저 56명 자동 제외).
- 기존 학습된 임베딩 모델(`user_profile_addi_202604_05`, `media_sequence_addi_genre_202604_05`)
  로 이 유저들만 추가로 추론.
- `scoring.build_stratified_pool`로 기존 5% 샘플 pool에 병합(우연히 샘플에 이미 있던
  22~24명은 전수 버전으로 대체). 병합 후 pool: 프로필 591,807명, 미디어 425,083명.

## 2. 불균형 처리 (코드 변경)

`scoring/train_supervised_lookalike.py`에 추가(별도 커밋, 코드 자체는 범용):

- **층화 미니배치 샘플링** (`--pos-frac`, 기본 0.1): 배치마다 양성을 강제로 섞는다(양성은
  복원추출). 순수 랜덤 배치는 대부분 양성 0건이라(pos_rate 0.09% × batch_size 512 ≈ 0.5명
  기댓값) 학습 신호가 너무 드물었다.
- **pos_weight를 배치 구성 비율 기준으로 재계산**: 원본 pos_rate(0.09%) 대신 층화된
  `--pos-frac`(0.1) 기준으로 계산 — 오버샘플링과 손실 가중치를 이중으로 겹치지 않게.
- **라벨 층화 train/val 분할**: val_frac(10%)을 양성/음성 따로 떼어 합침 — 순수 랜덤
  분할이면 val에 양성이 0건 걸릴 위험이 컸음(양성 388명의 10% ≈ 39명 정도라 운이 나쁘면
  0에 가까울 수 있었음).
- **평가지표 확장**: rank AUC 외에 PR-AUC(average precision), recall@top-K%(`--topk-pct`)를
  매 epoch 리포트. 음성이 압도적으로 많으면 AUC만으로는 상위권 랭킹 품질을 제대로 못 봄.

## 3. 재학습 실행

시드는 `03_seed_interested_users_apr_may.sql`(T2+ tier 기준) 대신 12번 쿼리 결과(IP+cmp_no
매칭, req_user_id 485명)를 `--seed-ids`로 직접 넘겼다 — **`03` 파일 자체는 아직 안 바꿈**,
두 트랙(T2+ / IP 매칭)을 병행할지 완전 대체할지는 아직 결정 안 됨.

```
.venv\Scripts\python.exe -m scoring.train_supervised_lookalike \
  --pool-profile-emb data/embeddings/user_profile_apr_may_stratified.csv \
  --pool-media-emb data/embeddings/media_sequence_apr_may_stratified.csv \
  --seed-ids data/raw/12_conv_matched_users_apr_may.csv \
  --model-out data/models/fusion_classifier_addi_conv_ip \
  --pos-frac 0.1 --topk-pct 0.1 --num-epochs 20
```

최종 학습 데이터(fused, profile∩media): 425,043명, 양성 388명(0.091%). train
382,538명(양성 349) / val 42,505명(양성 39, 라벨 층화 분할로 보장됨).

20 epoch 결과: `val_auc` 0.79~0.82(전 epoch 안정적), `val_pr_auc` 0.002~0.003(양성 자체가
워낙 희소해 절대값은 작지만 무작위 기준선 0.0009보다는 2~3배), `val_recall@top10%`은
0.13~0.31로 변동이 큼(val 양성이 39명뿐이라 epoch당 노이즈가 큼, epoch 1이 0.31로 가장
높았고 이후 등락). **조기 종료/베스트 체크포인트 저장은 구현하지 않음 — 마지막 epoch(20)
가중치를 그대로 저장했다.**

## 4. 백테스트 결과 (6월 postback 유저 269,914명, 라벨 동일)

기존(§2-5, 재학습 전 T2+ 모델) 대비 재학습 모델(IP 매칭 시드) 비교:

| 상위 % | 재학습 전 | 재학습 후 |
|---|---:|---:|
| 10% | 1.28× | **1.60×** |
| 20% | 1.19× | 1.44× |
| 30% | 1.28× | 1.22× |
| 50% | 1.18× | 1.15× |
| 100%(전체) | 1.00× | 1.00× |

decile 순서도 크게 개선됐다: 재학습 전엔 8구간(1.47×)이 10구간(1.28×)보다 높아 순서가 안
맞았는데, 재학습 후엔 하위 10%(0.45×)부터 상위 10%(1.60×)까지 거의 단조적으로 정리됐다
(중간에 5·7구간에서 작은 등락은 남아있음 — 표본이 작아 완전히 매끈하지는 않음).

**결론: 재학습이 실제로 개선했다.** 상위 10% lift가 1.28×에서 1.60×로 올랐고, 순위
단조성도 좋아졌다 — 5% 샘플링 문제 해결 + 불균형 처리가 헛수고가 아니었다는 근거.
