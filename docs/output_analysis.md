# 산출물 해석: postback 유저 실전환 예측 모델 검증 결과 (비전공자용)

`evaluation.backtest`가 뽑는 결과를 처음 보는 사람도 이해할 수 있도록 정리한 문서.
실행 방법은 [`README.md`](../README.md) §2-5, 원리는 [`model_architecture.md`](model_architecture.md) 참고.
아래 수치는 2026년 6월 postback(광고 반응) 유저 전체 기준(2026-07-09 재학습 모델) — 새로
백테스트를 돌리면 숫자는 바뀐다.

```
python -m evaluation.backtest --config config/backtest.example.json
```

## "전환"의 기준이 바뀌었다

이 문서의 예전 버전은 "postback(광고 반응) tier가 일정 수준 이상이면 전환"으로 봤다. 지금은
더 엄격하게, **postback이 발생한 유저 중 실제로 광고주 몰(mall)을 방문한 흔적(IP 매칭)이
있는 유저만 전환**으로 본다 — 광고를 봤다는 것과 실제로 그 광고주 사이트에 갔다는 것은
다른 얘기라서다. 배경/조사 과정은 [`docs/_archive/202607091533.md`](_archive/202607091533.md)
참고.

## 결론부터

2026년 6월에 광고에 반응(postback)한 유저 269,914명을 모델 점수로 줄 세운 다음, 실제로
몰까지 갔는지(IP 매칭 전환) 확인했다. 모델이 "전환 가능성이 높다"고 점수를 매긴 **상위 10%
그룹**은 실제 전환율이 전체 평균보다 **1.6배 높았다.** 반대로 "가능성이 낮다"고 본 **하위
10% 그룹**은 실제 전환율이 평균의 절반에도 못 미쳤다.

| 지표 | 값 |
|---|---|
| 분석 대상 postback 유저 | 269,914명 |
| 전체 평균 전환율 | 0.058% (156명) |
| 모델 상위 10% 그룹 전환율 | 0.093% (평균 대비 1.60배) |
| 모델 하위 10% 그룹 전환율 | 0.026% (평균 대비 0.45배) |

## 이걸 어떻게 확인했나

269,914명을 모델 점수 순으로 한 줄로 세운 다음, 앞에서부터 26,991~26,992명씩 10개 그룹으로
나눴다. **1번 그룹**은 모델이 "전환 안 할 것 같다"고 본 사람들, **10번 그룹**은 "전환할
것 같다"고 본 사람들이다. 그런 다음 실제로 누가 광고주 몰의 mall_ip와 매칭됐는지(IP+cmp_no
무관, 시간창 제한 없음 — `conv_matched_ip_any_cmp_any_window`) 확인해서 그룹별 실제
전환율을 비교했다.

**전환율 자체가 매우 낮다는 점에 주의**: 전체 평균이 0.058%(156명)뿐이라, 그룹당 전환자는
7~25명 수준이다. 표본이 작아서 그룹 사이 배율이 다소 들쭉날쭉할 수 있다 — 아래 "주의해서
볼 점" 참고.

## 상위 K%를 누적으로 보면

실무에서는 "상위 10%만 타겟팅" 대신 "상위 몇 %까지 타겟팅할까"를 결정해야 할 때가 많다.
아래는 상위 K%를 누적으로 뽑았을 때의 전환율이다(`evaluation.backtest --cumulative-output`):

| 상위 % | 인원 | 전환율 | 평균 대비 배율 |
|---|---|---|---|
| 10% | 26,992명 | 0.093% | 1.60× |
| 20% | 53,983명 | 0.083% | 1.44× |
| 30% | 80,975명 | 0.070% | 1.22× |
| 50% | 134,957명 | 0.067% | 1.15× |
| 100%(전체) | 269,914명 | 0.058% | 1.00× |

상위로 좁힐수록 배율이 꾸준히 올라간다 — 상위 10%만 타겟팅했다면 놓치는 인원은 많지만
전환율은 1.6배, 상위 절반까지 넓히면 전환율은 낮아지지만(1.15배) 더 많은 실제 전환자를
포함한다.

## 실무에 어떻게 쓰나

광고 예산과 노출 지면은 한정돼 있으니, postback 유저 전체에게 똑같이 후속 액션(리타겟팅
등)을 하는 대신 모델 점수가 높은 사람부터 우선순위를 매기면 같은 예산으로 더 많은 실제
전환을 끌어낼 수 있다. 다만 절대 전환자 수가 워낙 적어서(전체 156명), 어떤 K%를 고르든
실무 효과 체감은 크지 않을 수 있다 — 아래 "주의해서 볼 점" 참고.

## 주의해서 볼 점

- **절대 전환자 수가 매우 적다.** 전체 269,914명 중 156명(0.058%)만 전환으로 잡혀서,
  그룹당 7~25명 수준이다. 그룹 3~9번 사이의 순서(0.90×~1.28×)는 상당 부분 표본 노이즈일
  수 있다 — 양 극단(하위 10% 0.45×, 상위 10% 1.60×)의 차이만 신뢰도가 높다고 보는 게 맞다.
- **"전환"의 기준을 IP+mall_ip 매칭으로 넓게 잡았다.** cmp_no까지 요구하는 더 엄격한 기준
  (`conv_matched_ip_cmp_any_window`)으로 보면 전체 양성이 30명뿐이라 이런 그룹별 분석
  자체가 어렵다 — 표본 확보를 위해 IP만 매칭(cmp_no 무시)을 기본값으로 썼다.
- **이 결과는 특정 시점의 스냅샷이다.** 새로운 postback 데이터와 실제 전환 데이터가 쌓일
  때마다 같은 방식으로 다시 확인해서, 모델이 계속 잘 맞는지 주기적으로 점검해야 한다.
- **재학습 전/후를 비교하면 재학습이 실제로 도움이 됐다.** 재학습 전(기존 T2+ 시드로 학습된
  모델을 새 라벨에 그대로 적용)에는 상위 10% 배율이 1.28×였고 순서도 깔끔하지 않았다
  (`docs/_archive/202607091533.md`) — 재학습 후(층화 pool + 불균형 대응) 1.60×로 개선되고
  순서도 더 단조적으로 바뀌었다(`docs/_archive/202607091610.md`).

## 용어

- **그룹(분위, decile)**: 모델 점수 순으로 유저를 10등분한 구간. 이 문서에서는 1~10번으로
  표기(1=점수 최하위 10%, 10=점수 최상위 10%).
- **전환(라벨)**: postback 발생 유저 중 IP가 `"prod_addi_conv".raw_conv_web`/`raw_conv_web_imp`의
  `mall_ip`와 매칭되는 것(`--label-col conv_matched_ip_any_cmp_any_window`). 몰 페이지 방문
  기준이며, 실구매(`order` 이벤트)만으로 제한하면 표본이 거의 0에 수렴해 별도 분석이
  불가능하다.
- **배율(lift)**: 어떤 그룹의 실제 전환율 ÷ 전체 평균 전환율. 1.0보다 크면 평균보다 잘
  맞힌 것, 작으면 못 맞힌 것.
