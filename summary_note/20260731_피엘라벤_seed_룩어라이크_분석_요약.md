# 피엘라벤 Seed 기반 신규 유저 룩어라이크 분석 요약

## 0. 목표

피엘라벤(브랜드)에 관심 있는 것으로 확인된 사람들의 광고 ID 목록(이하 **seed**, 약 150만 개)을
갖고 있습니다. 이 사람들과 "특징이 비슷한" 사람을 아직 광고에 반응하지 않은 일반 유저 중에서
찾아내서, 새로운 타겟팅 후보 리스트로 쓰는 것이 목표입니다.

문제는 "특징이 비슷하다"를 컴퓨터가 판단하게 만들려면 그 사람이 어떤 사람인지(성별/나이/
사는 곳/관심사)를 알아야 하는데, seed 리스트 자체는 그냥 ID 목록일 뿐 그 사람이 누군지에
대한 정보가 없다는 것입니다. 그래서 아래 두 가지 데이터를 추가로 활용했습니다.

- **광고 노출 로그(bid log)**: 누가 언제 어떤 광고를 봤는지 기록된 데이터
- **세그먼트 데이터(skp)**: 그 사람이 어떤 특성(성별/연령대/사는 곳/관심사)을 가졌다고
  태깅된 데이터 — 광고 업계에서 흔히 쓰는 "이 사람은 이런 사람일 가능성이 높다"는 꼬리표 모음

이 문서는 이 두 데이터를 가지고 
(1) seed와 비슷한 사람을 찾는 계산 모델을 어떻게 만들었고,
(2) 그 결과가 실제로 말이 되는지 확인한 과정을 정리한 것입니다.

## 1. 전체 세그먼트 분석 결과 (모집단 전체 기준)

세그먼트 데이터는 한 사람당 6개 그룹의 꼬리표를 가질 수 있습니다.

| 그룹 | 꼬리표 종류 수 | 예시 |
|---|---|---|
| 성별 | 4개 | 여성(확신 높음/낮음), 남성(확신 높음/낮음) |
| 연령대 | 7개 | 20대, 30대, 40대 ... |
| 거주 | 241개 | 아파트, 서울 강남구, 펜션/리조트 방문 등 |
| 제품 관심사 | 418개 | 여성화장품, 골프용품, 자동차용품 등 |
| 콘텐츠 관심사 | 184개 | IPTV 드라마, 뉴스, 영화 등 시청 이력 기반 |
| 기타(라이프스타일) | 129개 | MZ세대, 대학생, OTT 관심자 등 |

전체 광고 노출 로그 모집단(약 7,225만 명) 중 **세그먼트 꼬리표가 하나라도 있는 사람은
21.8%(약 1,555만 명)** 입니다. 나머지 78%는 이 회사 DMP(세그먼트 제공사)가 아예 태깅하지
않은 사람이라는 뜻입니다 — 즉 세그먼트 데이터는 "전 국민"이 아니라 "이 DMP가 알고 있는
사람"만 커버합니다. 아래 표는 **"세그먼트가 하나라도 있는 사람" 전체(약 5,334만 명)를
기준**으로, 각 그룹에서 가장 흔한 항목 top10과 그 비율입니다(2번의 seed 표와 같은
항목·같은 순서로 비교할 수 있게 뽑았습니다).

| 그룹 | 그룹 내 태그를 하나라도 가진 사람 비율(전체 5,351만 명 중) | 전체 모집단 기준 상위 항목과 비율 |
|---|---|---|
| 거주 | 34.0% | 아파트 17.0%, 자동차 관련 장소 13.1%, 테마레저 12.9%, 분식 12.0%, 펜션/리조트 10.2%, 한식 9.8%, 병원/의원 8.8%, 마트 7.3%, 전문음식점 7.1%, 지하철/기차 관련 장소 6.7% |
| 기타(라이프스타일) | 54.6% | 엔터테인먼트 관심자 23.0%, MZ세대 22.8%, 갤럭시 이용자 20.2%, 다이어트 운동 관심자 19.9%, 재테크 투자 부동산 관심자 15.3%, 다이어트 관심자 14.7%, 커피/카페 관심자 14.3%, 게임 관심자 12.9%, 영화 매니아 및 관심자 11.9%, OTT 관심자 11.7% |
| 콘텐츠 관심사 | 28.2% | 페이먼트/송금 앱 13.0%, 카드 관련 앱 12.4%, 음악/오디오 관련 앱 12.3%, 지도/대중교통 관련 앱 12.0%, 헬스케어 앱 11.8%, 쇼핑/오픈마켓 앱 11.7%, 은행 관련 앱 10.9%, 생산성 관련 앱 10.7%, IPTV 9.5%, 연예/오락 9.2% |

| 성별 | 43.9% | 남성(확신 낮음) 36.6%, 남성(확신 높음) 18.2%, 여성(확신 낮음) 15.9%, 여성(확신 높음) 13.0% |

*(이 컬럼은 `eda/queries/21_group_coverage_full_population.sql` 실행 결과 기준 — 이
쿼리를 돌린 날짜의 전체 인원은 5,351만 명으로, 위 top10 비율을 계산한 날짜의 5,334만
명과 데이터가 하루 정도 갱신되며 약간(0.3%) 달라졌지만 결론에 영향을 줄 정도는 아닙니다.)*

> **왜 성별 4개 항목을 더해도 100%가 안 될까? (실측 결과로 답함)** 이 4개는 서로
> 배타적인 카테고리가 아닙니다. 한 사람이 "남성(확신 낮음)"과 "남성(확신 높음)"을
> **동시에** 갖는 경우가 흔해서(평균 1.95개씩 동시 보유), 개별 항목을 단순히 더하면
> 겹치는 사람을 중복으로 세게 됩니다. `21_group_coverage_full_population.sql`로 한
> 사람당 성별 점수를 하나로 정리해서 다시 세어보니:
>
> | 판정 | 인원 | 전체(5,351만 명) 중 비율 |
> |---|---|---|
> | 남성으로 판정 | 1,527만 9,941명 | 28.6% |
> | 여성으로 판정 | 384만 4,062명 | 7.2% |
> | 판정 불가("모름": 태그 없음 + 남녀 태그가 서로 상쇄돼 판정 안 되는 경우 포함) | 3,438만 7,542명 | 64.3% |
>
> 즉 **성별이 확인된 사람(1,912만 4천 명, 전체의 35.7%)만 놓고 보면 남성 79.9% :
> 여성 20.1%로, 남성이 압도적으로 많습니다.** (참고로 성별 태그가 하나라도 있는
> 사람은 전체의 43.9%인데, 그중 18.7%(약 439만 명)는 남녀 태그가 동시에 붙어 있어서
> 서로 상쇄되어 "모름"으로 처리됩니다.) 이 결과는 2번 절의 seed-모집단 비교표에서
> 기존에 썼던 "전체 모집단 남성 54.8%"라는 값이 부정확한 근사치였음을 보여주는데,
> 이유와 수정 내용은 2번 절에 반영했습니다.

분포를 더 자세히 뜯어보면(원 CV 분석은 `eda/docs/segment_distribution_report.md` 참고):

- **거주/관심사 그룹은 쏠림이 있습니다** — 예를 들어 거주 그룹은 "아파트" 하나가 전체의
  4.16%를 차지하는데, 만약 241개 항목에 골고루 나뉘어 있었다면 각 항목이 0.415%씩만 가져야
  합니다. 즉 "아파트"가 공평한 몫의 10배를 차지하는 셈입니다.
- **성별/연령대는 항목 수 자체가 적어서(4개, 7개)** 쏠림이 있어도 극단적이진 않습니다.
- 제품 관심사(418개)는 항목 수가 많다 보니 쏠림이 소수에 집중되기보다 넓게 퍼져 있습니다
  (역설적으로 "제품 관심사"의 원시 쏠림 수치가 더 낮게 나오는 이유).

## 2. Seed 세그먼트 분석 결과

**seed 150만 명 중 실제로 진짜 광고용 기기 ID(GAID)로 연결할 수 있었던 사람은 92만
8,809명(61.2%)** 입니다(나머지 39%는 이 DMP가 태깅하지 않은 사람이거나 ID 연결이 안
되는 경우 — 자세한 이유는 4번 참고).

여기서 숫자가 한 번 더 갈립니다 — **한 사람이 기기 ID 여러 개로 연결되는 경우가
있습니다.** 예를 들어 과거에 광고 ID를 리셋하거나 기기를 바꾼 이력이 있으면, 옛날 ID와
최근 ID가 둘 다 변환 기록에 남아있어서 한 사람이 평균 2.7개의 기기 ID를 갖게 됩니다.
그래서 92만 8,809명(**사람 수**)이 변환되면 251만 9,634개의 기기 ID(**기기 ID 레코드
수**, 사람 수 아님)가 되고, 그 중 세그먼트 데이터가 붙어있는 기기 ID는 249만 6,351개
(전체 기기 ID의 99.1%)입니다.

**즉 아래 표의 "249만 6,351건"은 "사람 수"가 아니라 "세그먼트 데이터가 있는 기기 ID
레코드 수"입니다** — 같은 사람이 여러 번 중복으로 들어있을 수 있다는 뜻입니다. 다만
비율(%)로 보는 통계(성별 분포, 관심사 top10 등)에는 이 중복이 실제 결과를 크게 왜곡하지
않습니다 — 한 사람의 여러 기기 ID는 대부분 같은 세그먼트 값을 가지기 때문입니다(같은
사람의 옛날/최신 기기라서).

이 **249만 6,351건 전체**를 통계 낸 결과:

| 항목 | 결과 |
|---|---|
| 성별 확인 가능 | 101만 9,244건/250만 건(40.8%) — 남성 53만 6,637건, 여성 48만 2,607건 (확인된 것 중 52.7%:47.3%) |
| 연령대 확인 가능 | 50만 7,973건/250만 건(20.3%) — 30대(21.1만) > 40대(16.5만) > 50대(8.8만) 순 |
| 콘텐츠 관심사 top10 | 전부 IPTV 시청 관련(연예오락 67%, 드라마 66%, 교양정보 66%, 뉴스 65% 등) |
| 거주 top10 | 아파트(22.7%), 자동차 관련 장소(19.0%), 분식(18.3%), 테마레저(18.1%), 한식(16.0%) |
| 기타(라이프스타일) top10 | MZ세대(71.5%), 엔터테인먼트 관심자(69.2%), OTT 관심자(68.8%), 대학생(67.9%) |
| 제품 관심사 top10 | 농수축산물(5.1%), 여성화장품(4.9%), 스킨케어(4.4%), 스포츠의류(4.2%), 여성의류(4.0%) |

**해석**: 피엘라벤 seed는 "IPTV/OTT로 미디어를 많이 소비하고(전체의 약 60~70%가 해당),
아파트에 살며 여행/레저(테마레저·펜션리조트)에 관심 있는, 뷰티/식품/스포츠 관심이 있는
MZ세대/대학생 성향의 사람들"이라는 특징이 뚜렷합니다. 다만 성별·연령대는 확인 가능한
비율이 각각 40.8%/20.3%뿐이라 나머지는 "모름" 상태라는 점은 감안해야 합니다.

### Seed 분포는 "모집단을 그대로 따르는 것"인가, "seed만의 특징"인가?

같은 항목을 1번(전체 모집단, 5,334만 명)과 나란히 놓고 비교하면 그룹마다 답이 다릅니다.

| 그룹 | 대표 항목 | 전체 모집단 | Seed | 배율(seed÷전체) | 판정 |
|---|---|---|---|---|---|
| 거주 | 아파트 | 17.0% | 22.7% | 1.3배 | **순위·구성은 거의 동일, 비율만 다소 높음** — 모집단 패턴을 대체로 따름 |
| | 테마레저 | 12.9% | 18.1% | 1.4배 | |
| 제품 관심사 | 여성화장품 | 1.6% | 4.9% | **3.1배** | **순위(1~2위)는 모집단과 같지만 비율은 3배** — 모집단 패턴 + seed 강화 |
| | 농수축산물 | 2.0% | 5.1% | 2.6배 | |
| 콘텐츠 관심사 | IPTV | 9.5% | 67.9% | **7.1배** | **구성 자체가 다름** — 모집단 top10은 "보유앱"(페이먼트/카드/은행 앱) 위주인데 seed는 "IPTV 시청" 위주로 완전히 다른 항목이 상위를 차지 |
| 기타(라이프스타일) | MZ세대 | 22.8% | 71.5% | **3.1배** | **비율이 훨씬 높고, 항목 구성도 일부 다름**(seed에만 상위인 "대학생", "야구 관심자" 등) |
| | OTT 관심자 | 11.7% | 68.8% | **5.9배** | |
| 성별 | 여성 비중(확인된 것 중) | 20.1% | 47.3% | **2.4배** | **차이 뚜렷함** — seed는 모집단보다 여성 비중이 훨씬 높음(모집단은 남성 79.9%로 압도적인데, seed는 남녀가 52.7%:47.3%로 거의 반반) |
| 연령대 | 30대 | 4.6% | 8.5% | 1.8배 | 전체 대비 seed가 다소 높지만, 태깅 자체가 잘 안 되는 그룹(전체 태그 확인 비율 11.2%)이라 |
| | 40대 | 2.9% | 6.6% | 2.3배 | 해석에 참고만 할 것(4번 참고, seed는 태깅 비율 자체도 20.3%로 더 높음) |

**참고(성별 행 계산 방식, 2026-07-31 수정)**: 처음에는 전체 모집단의 "남성 비중"을 1번
표의 "남성(확신 낮음) 36.6%+남성(확신 높음) 18.2%=54.8%"로 단순히 더해서 seed의 52.7%와
비교했는데("거의 차이 없음"), 이 두 항목은 겹치는 사람이 있어(위 1번 절 설명 참고) 단순
합은 부정확했습니다. `21_group_coverage_full_population.sql`로 seed와 똑같은 방식(한
사람당 성별 점수를 평균 내 남성/여성/모름 하나로 정리)으로 모집단을 다시 계산해보니,
확인된 사람 중 남성이 실제로는 **79.9%**(여성 20.1%)로 훨씬 더 치우쳐 있었습니다. 즉
성별은 "seed를 구분하는 특징이 아니다"가 아니라 **정반대로, seed가 모집단보다 훨씬
여성 친화적이라는 뚜렷한 특징**이었습니다.

**결론**: 거주와 제품 관심사는 "모집단에서도 원래 흔한 항목이 seed에서도 그대로 흔하고,
다만 강도가 1.3~3배 세다" 정도라 **모집단 패턴을 상당 부분 따라가면서 조금 더
강조된 형태**입니다. 반면 **콘텐츠 관심사(IPTV 시청)와 기타(라이프스타일, MZ세대/OTT)는
비율이 3~7배까지 벌어지고 상위 항목 구성 자체도 달라서, 이건 모집단 전체의 일반적인
경향이 아니라 seed(피엘라벤 관심 유저)만의 뚜렷한 특징**이라고 볼 수 있습니다. **성별도
구분 요인입니다** — 모집단은 남성 쪽으로 크게 치우쳐 있는데(79.9%) seed는 남녀가 거의
반반(52.7%:47.3%)이라, "seed는 모집단보다 여성 비중이 훨씬 높다"는 것도 seed만의 뚜렷한
특징 중 하나입니다.

**참고**: 아래 3번의 "후보(candidate) 66,469명"은 이런 크로스워크 fan-out 과정을 거치지
않고 bid log에서 바로 뽑은 값이라, 위와 같은 중복 문제가 없습니다(사람 수 ≈ 기기 ID 수).
seed 쪽만 크로스워크를 거쳤기 때문에 생긴 차이입니다.

## 3. 추출한 신규 후보의 세그먼트 분석 및 Seed와 비교

"신규 후보"는 (1) seed 리스트에 없고 (2) 2026년 6월에 광고 활동이 있었고 (3) 세그먼트
데이터가 있는 사람으로 정의했습니다 — 총 **664,684명**. 이 사람들에게 seed와 얼마나
비슷한지 0~1 사이 점수를 매겨서, **점수 상위 10%(66,469명)** 를 최종 후보로 뽑았습니다.

이 **상위 10% 66,469명 전체**를 seed 249만 6,351건(2번 참고 — 사람 수 아니라 기기 ID
레코드 수) 전체와 같은 방식으로 비교한 결과:

| 항목 | Seed 전체(약 250만 건, 기기ID 기준) | 후보 전체(66,469명) | Top10 겹침 |
|---|---|---|---|
| 콘텐츠 관심사 | IPTV/연예오락/드라마 등 60~68% | IPTV/연예오락/드라마 등 60~73%(오히려 비율 더 높음) | **10/10 항목 동일** |
| 거주 | 아파트 22.7%, 테마레저 18.1% 등 | 아파트 36.4%, 테마레저 30.9% 등(비율은 더 높음) | **10/10 항목 동일** |
| 제품 관심사 | 농수축산물 5.1%, 여성화장품 4.9% 등 | 농수축산물 8.6%, 여성화장품 8.5% 등(비율은 더 높음) | **9/10 항목 동일** |
| 기타(라이프스타일) | MZ세대 71.5%, 엔터관심자 69.2% 등 | MZ세대 92.1%, 엔터관심자 90.5% 등(비율은 훨씬 높음) | **8/10 항목 동일** |
| 성별(확인된 사람 중) | 남52.7%:여47.3% | 남49.4%:여50.6% | 비슷 (참고: 둘 다 전체 모집단의 남79.9%:여20.1%와는 크게 다름 — 2번 참고) |
| 연령대 확인 비율 | 20.3% | 36.8%(더 넓게 확인됨) | 후보 쪽이 태깅이 더 잘 됨 |

**해석**: 전체 인원으로 다시 계산하니 네 그룹(콘텐츠/거주/제품/기타) 전부 상위 10개 항목이
8~10개씩 그대로 겹칩니다 — **150명 표본으로 봤을 때 "제품 관심사만 다르다"고 봤던 건
표본이 작아서 생긴 착시**였습니다(150명 표본에선 4/10, 전체로 보면 9/10). 오히려 후보
그룹은 seed와 같은 항목들이 **비율 자체가 더 높게** 나타납니다(예: MZ세대가 seed는
71.5%인데 후보는 92.1%) — 이는 상위 10% 후보가 "seed와 가장 닮은 사람"만 걸러낸
결과이기 때문에 자연스러운 현상입니다.

## 4. 쿼리들의 필터링 방법

데이터를 뽑을 때 아래 기준들을 일관되게 적용했습니다.

- **개인정보 동의 필터**: 데이터 수집에 동의하지 않았거나(값이 비어있는 경우도 보수적으로
  제외) 옵트아웃(추적 거부)한 사람은 전부 제외했습니다.
- **기간 분리**: 모델을 학습시키는 데 쓴 기간(2026년 4~5월)과, 실제로 신규 후보를 뽑는 데
  쓴 기간(2026년 6월)을 겹치지 않게 나눴습니다 — 학습에 쓴 사람으로 시험까지 보면 실력을
  과대평가하게 되기 때문입니다.
- **ID 연결(크로스워크) 문제 발견 및 해결**: seed 리스트의 ID가 세그먼트 데이터의 ID
  체계와 다른 방식으로 저장돼 있다는 걸 뒤늦게 발견했습니다(예: 같은 사람이라도 시스템마다
  다른 이름표를 붙여놓은 상황). 처음엔 이 때문에 seed와 세그먼트 데이터가 거의 연결되지
  않았는데(0.0%), 중간 변환 테이블을 거쳐 두 ID를 연결하는 방법을 찾아서 61.2%까지
  끌어올렸습니다.
- **표본 추출 계산 실수 발견 및 수정**: 일반 유저 중 일부만 뽑아 학습에 쓰려고 했는데,
  처음 계산 방식에 실수가 있어 의도한 것보다 훨씬 많은 사람이 뽑혔던 걸 발견하고 바로잡았습니다.
- **"신규 후보" 정의를 한 번 바꿈**: 처음엔 무작위로 일부만 뽑으려 했는데, 그러면 세그먼트
  데이터가 있는 사람이 1.6%뿐이라 비교 자체가 의미 없어져서, "세그먼트 데이터가 있는
  사람"이라는 조건으로 후보 정의를 바꿨습니다(3번 결과가 이 정의를 쓴 것).
- **중복 집계 발견 및 수정**: 4~5월에도 활동했고 6월에도 활동한 사람이 두 번 중복으로
  계산되던 것을 발견해서 한 번만 세도록 고쳤습니다.

## 5. 임베딩 아키텍처 및 학습 방법

**1단계 — 특징 압축(임베딩) 학습**: 한 사람의 세그먼트 꼬리표(성별/연령대/거주/관심사)를
32개의 숫자로 이루어진 "요약 카드"로 압축하는 모델을 만들었습니다. 이 모델은 "압축했다가
다시 원래 정보로 복원하는" 연습을 반복해서, 압축된 요약 카드가 원래 특징을 최대한 잘
담도록 스스로 학습합니다(라벨이나 정답 없이 데이터 자체로 학습하는 방식). 약 571만 명
(seed+일반유저+후보)을 대상으로 GPU로 약 3시간 학습시켰습니다.

### 1단계 상세 — 세그먼트 그룹별로 압축 방식이 다릅니다

6개 그룹은 성격이 서로 달라서(숫자 하나짜리 성별부터, 항목이 418개나 되는 제품
관심사까지) 그룹마다 다른 방식으로 숫자로 바꿨습니다.

| 세그먼트 그룹 | 원본 형태 | 임베딩(숫자로 바꾸는) 방식 | 압축 후 차원 |
|---|---|---|---|
| 성별 | 4개 항목(여성/남성 × 확신 높음/낮음) | **스코어링**: 한 사람이 가진 성별 태그들을 -1(남성 확신)~+1(여성 확신) 사이 점수 하나로 미리 평균 내서 계산(2번 절의 "왜 100%가 안 되는지" 설명과 같은 방식). 학습 없이 그 점수를 그대로 사용 | 1 |
| 연령대 | 7개 항목(10대~70대 이상) 중 1개 또는 없음 | **학습형 임베딩(nn.Embedding)**: "몇 번째 연령대인지"라는 카테고리 번호를 학습 가능한 8칸짜리 숫자 벡터로 변환. 항목 수가 적어(7개+모름) 원핫인코딩과 비슷하지만, 학습 과정에서 벡터 값 자체가 조정된다는 점이 원핫과 다름(예: 30대와 40대가 비슷한 특성을 보이면 학습 중 벡터도 서로 가까워짐) | 8 |
| 거주 | 최대 72개 항목(241개 항목 중 다중 선택) | **텍스트 임베딩(BERT) + 평균 풀링**: 아래 설명 참고 | 768→32 |
| 제품 관심사 | 최대 24개 항목(418개 항목 중 다중 선택) | 거주와 동일한 방식(같은 BERT lookup 공유) | 768→16 |
| 콘텐츠 관심사 | 최대 48개 항목(184개 항목 중 다중 선택) | 거주와 동일한 방식(같은 BERT lookup 공유) | 768→16 |
| 기타(라이프스타일) | 최대 48개 항목(129개 항목 중 다중 선택) | 거주와 동일한 방식(같은 BERT lookup 공유) | 768→16 |

**거주/제품 관심사/콘텐츠 관심사/기타, 이 4개 그룹에 쓴 "텍스트 임베딩" 방식**:

1. 각 세그먼트 항목은 "목적지/거주지 > 목적지(업종) > 주택/주거 > 아파트"처럼 계층
   구조를 가진 이름표(텍스트)를 갖고 있습니다. 이 텍스트를 사전학습된 한국어 문장
   임베딩 모델(`jhgan/ko-sroberta-multitask`)에 한 번 통과시켜서, 항목 하나당 768개
   숫자로 된 벡터를 미리 만들어 둡니다 — "아파트"와 "빌라"처럼 뜻이 비슷한 항목은
   벡터도 자연히 서로 가깝게, "아파트"와 "카페"처럼 뜻이 다른 항목은 벡터도 멀게
   나옵니다(우리 데이터를 학습한 게 아니라, 원래 한국어 문장 의미를 이해하도록 미리
   학습된 범용 모델을 그대로 가져다 쓴 것입니다).
2. 이 4개 그룹은 항목 개수가 많고(129~418개) 한 사람이 여러 개를 동시에 가질 수
   있어서, 그 사람이 가진 항목들의 768차원 벡터를 **평균**내서 "이 사람의 거주/관심사
   프로필"을 벡터 하나로 요약합니다(항목을 최대 24~72개까지만 반영, 그 이상은 자름 —
   실제 데이터에서 한 사람이 갖는 항목 개수의 상위 99% 수준에 여유를 둔 값입니다).
3. 768차원은 숫자가 너무 많아서(성별 1개, 연령대 8개짜리 벡터를 압도해버림) 그룹별로
   각각 더 작은 차원(거주 32, 나머지 16)으로 다시 한번 줄이는 계산(Linear 변환)을
   거칩니다. 이 축소 과정 자체도 학습 대상이라, 처음엔 범용 문장 의미로 시작했다가
   학습을 거치며 "피엘라벤 seed를 구분하는 데 실제로 중요한 방향"으로 조금씩 조정됩니다.

이렇게 나온 6개 조각(성별 1 + 연령대 8 + 거주 32 + 제품 16 + 콘텐츠 16 + 기타 16 =
총 89개 숫자)을 한 줄로 이어붙인 뒤, 다시 한번 작은 신경망(89→64→32)에 통과시켜서
최종 32개 숫자짜리 "요약 카드"(z)를 만듭니다. 학습할 때는 이 z를 거꾸로 다시 89개
숫자(원래의 성별 점수/연령대/그룹별 프로필)로 복원하는 연습을 반복시켜서, z가 원본
정보를 최대한 잘 담도록 만듭니다 — 복원에 쓰는 목표값은 최적화가 서로 얽히지 않도록
계산 그래프에서 분리(detach)해둡니다.

**2단계 — "seed와 닮았는지" 판별 학습**: 위에서 만든 요약 카드(32개 숫자)를 가지고,
"이 사람이 seed인지 일반 유저(pool)인지"를 구별하는 간단한 판별 모델을 학습시켰습니다.
seed 약 250만 명, 일반 유저 약 255만 명으로 학습했고, 결과는 **AUC 0.868**로 나왔습니다.
(AUC는 판별 능력을 0.5~1 사이로 나타낸 점수입니다 — 0.5면 동전 던지기 수준으로 전혀
못 맞추는 것, 1.0이면 완벽하게 구별하는 것. 0.868은 꽤 잘 구별한다는 뜻입니다.)

**3단계 — 신규 후보 채점**: 학습된 판별 모델에 "6월에 활동한 신규 유저"의 요약 카드를
넣어서 "seed와 얼마나 닮았는지" 0~1 사이 점수를 매기고, 점수가 높은 순으로 정렬해서
상위 10%를 최종 후보로 뽑았습니다.

## 7. 한계와 다음 단계

  "신규 후보"는 정의상 아직 반응하지 않은 사람들이라, 실제 캠페인을 집행한 뒤 이 사람들이
  얼마나 반응하는지를 봐야 진짜 성능을 알 수 있습니다.

  나머지는 "모름" 상태라, 이 두 축은 비교/판단의 근거로 쓰기엔 근거 데이터 자체가 얇습니다.
- **1단계 압축 모델 학습이 약간 불안정했습니다** — 학습 중간(11번째 반복)에 가장 좋았다가
  이후 다시 나빠지는 현상이 있었는데, 지금 모델은 마지막 시점 것만 저장되어 있어 가장 좋은
  시점 모델을 못 씁니다. 추후 개선 여지가 있습니다.

|---|---|
| Seed | 이미 피엘라벤에 관심 있다고 확인된 사람들의 광고 ID 목록 |
| Pool | 학습에 쓸 "일반 유저" 비교군(양성=seed과 대비되는 음성 표본) |
| 후보(Candidate) | 아직 반응하지 않은, 새로 타겟팅해볼 만한 사람 목록 |
| device_ifa | 스마트폰/기기별로 광고 업계에서 쓰는 고유 식별자(사람이 아니라 기기 기준) |
| 세그먼트(Segment) | "이 사람은 이런 특성을 가졌을 가능성이 높다"는 꼬리표. 광고 데이터 제공사(DMP)가 여러 정보를 조합해 추정해서 붙임 |
| 임베딩(Embedding) | 여러 정보를 압축한 숫자 벡터(요약 카드) |
| AUC | 분류 모델이 두 그룹을 얼마나 잘 구별하는지 나타내는 점수(0.5=무작위, 1.0=완벽) |
| 크로스워크(Crosswalk) | 서로 다른 시스템의 ID 체계를 연결해주는 변환 작업 |
