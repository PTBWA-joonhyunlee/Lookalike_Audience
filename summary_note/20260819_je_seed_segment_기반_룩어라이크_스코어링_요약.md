# je Seed(1,157명) segment 임베딩 기반 lookalike 스코어링 요약 (candidate 확장판)

## 0. 목표

새 브랜드 seed(`je_sample_adid.csv`, raw GAID 1,922명 — [`eda/queries/28_seed_je_id_space_check.sql`](../eda/queries/28_seed_je_id_space_check.sql)로 크로스워크 불필요 확인됨)를 피엘라벤
트랙에 붙여 lookalike 후보를 뽑았다. 1차 스코어링(candidate 664,684명, 06월만) 결과
상위20%가 목표(30만 명)에 크게 못 미쳐, candidate 모집단을 06월→06~08월18일로 넓히고
**같은 김에 seed_je도 candidate 제외 조건에 추가**(1차 때 발견된 "candidate에 je seed
본인 1,063명이 섞여있던" 오염 수정)한 뒤 재스코어링한 결과를 정리한다. segment 임베딩은
여전히 **재학습 없이** 피엘라벤 트랙에서 이미 학습된 `segment_features` Autoencoder로
인코딩만 했고(신규 candidate 분만 [`build_features_incremental.py`](../seed/embedding/segment_features/build_features_incremental.py)+[`append_embeddings.py`](../seed/inference/append_embeddings.py)로 추가 인코딩), lookalike
분류기(`segment_je` variant)도 재학습하지 않고 1차 때 학습된 모델을 그대로 candidate
확장판에 다시 스코어링했다.

### 0-1. pool/candidate 추출 방식 — 기간·필터·샘플링

| | seed(je) | pool | candidate |
|---|---|---|---|
| 기간 | skp 최신 스냅샷(기간 파티션 필터 없음) | 2026-04~05 | **2026-06~08월18일**(1차: 06월만) |
| 대상 | `seed_je_ad_id`(1,922명) ∩ skp 세그먼트 매칭 | 전체 모집단(seed_piellaven 제외) | KR + "Android"(`device_osv` 숫자 필터) + skp 세그먼트 매칭 + **seed_piellaven·seed_je 둘 다 제외**(1차: piellaven만) |
| region/OS 필터 | 없음 | **없음**(skp 테이블 자체에 region/OS 컬럼이 없어 적용 불가) | KR + Android |
| 샘플링 | 전수(1,157명) | 5%(`mod(crc32(device_ifa),1000)<50`) | 100%(샘플링 없음) |
| 쿼리/테이블 | [`segment/02_seed_segment_je.sql`](../seed/queries/segment/02_seed_segment_je.sql)(재사용) | [`segment/01_pool_segment.sql`](../seed/queries/segment/01_pool_segment.sql)(재사용) | [`segment/03_create_candidate_table.sql`](../seed/queries/segment/03_create_candidate_table.sql)(2026-08-19 확장, `candidates_202606_0818`)+[`04_candidate_segment.sql`](../seed/queries/segment/04_candidate_segment.sql) |

**규모 변화가 예상보다 훨씬 컸다**: 06월만→06~08월18일(1개월→약 2.6개월, 배수로는
2.6배)로 늘렸는데 실제 candidate 규모는 664,684명→**3,845,655명(5.8배)**로 늘었다 —
일별 활동 유저가 겹치지 않고 계속 새로 유입되는 만큼 "누적 unique 디바이스 수"가
기간에 선형보다 더 빠르게 늘어난 것으로 보인다(예상했던 약 150만 명을 크게 초과).

**오염 수정 확인**: 1차에서 candidate 664,684명 중 1,063명(0.16%)이 실제 je seed
본인이었는데, 이번엔 `seed_je_ad_id`도 candidate 제외 조건에 추가해 **오염이 0명으로
사라졌다**(직접 조인 확인: candidate 3,845,655명 중 seed_je와 겹치는 인원 0명).

## 4. 모델 학습/스코어링 결과

- **variant**: `segment_je`([`scoring/config.py`](../seed/scoring/config.py)) — 분류기는 1차 학습분을 그대로 재사용(재학습 없음),
  candidate 확장분만 기존 Autoencoder로 추가 인코딩(`build_features_incremental.py` →
  `inference.segment_features` → `append_embeddings.py`).
- **candidate 스코어링**: 3,845,655명 전원 스코어(0~1), 평균 0.306, 중앙값 0.316, 상위10%
  컷오프 **0.6754**, 상위10% = **384,567명**.
- **목표(상위20%=30만 명) 대비**: candidate가 예상보다 훨씬 크게 늘어(3,845,655명)
  **상위10%만 해도 384,567명으로 이미 목표(30만)를 넘는다.** 정확히 30만 명이
  필요하다면 상위10%가 아니라 **상위 약 7.8%**(300,000 ÷ 3,845,655)로 다시 뽑아야
  한다 — `infer_lookalike.py --variant segment_je --top-pct 7.8`로 재실행하면 된다.
- **오염 재확인**: candidate 3,845,655명과 상위10% 384,567명 모두 je seed 본인과의
  겹침이 **0명**으로 확인됐다(1차 1,063명 → 0명, 0-1절 SQL 수정이 의도대로 반영됨).

## 5. 한계 / 다음 단계

- **candidate 규모가 목표보다 훨씬 커짐**: 06~08월18일 확장이 예상(약 150만)보다 2.5배
  더 커졌다(3,845,655명) — 원인은 "일별 신규 유입 유저가 계속 쌓이는" 누적 효과로
  추정되나 정확히 검증하지 않았다. 정확히 30만 명 단위로 후보를 뽑으려면 top-pct를
  다시 계산하거나(4번 절 참고), candidate 기간을 다시 좁히는 것도 고려할 것.
- **pool은 여전히 seed_je를 제외하지 않음**: candidate와 달리 pool(`01_pool_segment.sql`)은
  이번에 손대지 않아 seed_je와의 겹침이 여전히 64명(pool 2,549,024명 중 0.003%) 남아있다
  — 규모상 무시 가능한 수준이나, pool도 완전히 정리하려면 seed_je_ad_id 제외 조건을
  추가해 재추출해야 한다.
- **seed 커버리지 반쪽만 반영**: seed_je 1,157명은 크로스워크 확인된 1,922명 중 skp
  세그먼트가 있는 60.2%뿐이다 — 나머지 765명의 성향은 이 모델에 반영되지 않았다.
- **pool-candidate 모집단 정의 불일치**: pool은 region/OS 필터가 없는데 candidate는
  KR+Android 필터가 있다 — 피엘라벤 segment 트랙에서 이미 알려진 한계([`01_pool_segment.sql`](../seed/queries/segment/01_pool_segment.sql)
  주석 참고)가 je에도 그대로 이어진다.
- **학습 성능 지표 없음**: val_auc 등 정량 지표가 기록되지 않아 분류기 품질을 스코어
  분포와 seed 겹침 sanity check만으로 간접 판단했다.
